# SHAUGHV CDN

`cdn.shaughv.com` is Emmett Shaughnessy's private CDN for SHAUGHV brand assets, licensed
fonts (Makira + IBM Plex Mono), and a small set of shared vanilla-JS drop-ins (animated
brand mark, loader). It's a Cloudflare R2 bucket served behind a custom domain — no
Worker, no auth, open CORS on `GET`/`HEAD`.

Anything SHAUGHV-branded in the browser should pull from here rather than ship its own
copy of these assets. The CDN is the canonical source of truth.

- **Base URL:** `https://cdn.shaughv.com`
- **Backend:** Cloudflare R2 (custom domain → bucket)
- **CORS:** open (`*`) on `GET`/`HEAD` — `<link>`, `<script>`, `<img>`, `fetch()` all work cross-origin without preflight friction
- **Source repo (private):** `https://github.com/RealEmmettS/shaughv-cdn`
- **Live asset inventory:** the README's auto-generated *Live URL map* block — https://github.com/RealEmmettS/shaughv-cdn/blob/main/README.md#live-url-map

If you need an asset and aren't sure of the exact URL, point the user at the Live URL map
in the README. It's regenerated by `scripts/generate-url-table.sh` on every asset change,
so it's always current.

## The three URL families

```
https://cdn.shaughv.com
├── /brand/shaughv/
│   ├── logos/                   wordmark — SVG + PNG fallbacks
│   ├── favicons/                icon-mark (mustache + glasses), light/dark, alt variants
│   └── figurines/               mascot illustrations
│       └── transparent/           background-removed variants of the same figurines
├── /fonts/
│   ├── makira/                  SHAUGHV display family — Makira Sans-Serif (commercial, self-hosted)
│   │   ├── makira.css             one stylesheet, every weight as @font-face
│   │   ├── otf/  ttf/  woff/  woff2/  variable/
│   └── ibm-plex-mono/           SHAUGHV monospace — IBM Plex Mono (SIL OFL 1.1)
│       ├── ibm-plex-mono.css      one stylesheet, every weight as @font-face
│       └── ttf/  woff/  woff2/
└── /js/                         zero-dep vanilla drop-ins
    ├── animated-brand-mark.js   defines <shaughv-mark> custom element + draw-on animation loop
    ├── shaughv-loader.js        defines <shaughv-loader> custom element
    └── react/
        └── AnimatedBrandMark.jsx  React + Framer Motion source port (raw JSX, needs a bundler)
```

The repo's directory layout maps 1:1 to URL paths. If you see `brand/shaughv/figurines/figurine-header.webp`
in the source repo, the URL is `https://cdn.shaughv.com/brand/shaughv/figurines/figurine-header.webp` —
no rewriting, no extra prefix.

## Canonical usage snippets

### Animated brand mark (vanilla, recommended)

```html
<style>
  .brand-mark { display: inline-block; height: 64px; width: 64px; color: #fff; }
</style>
<shaughv-mark class="brand-mark" aria-label="SHAUGHV"></shaughv-mark>
<script src="https://cdn.shaughv.com/js/animated-brand-mark.js"></script>
```

The mark inherits its color from CSS `currentColor`. **Hard minimum:** `64 × 64 px`.
Below that, fall back to the static wordmark — the path-drawing animation looks broken at
smaller sizes.

### Static wordmark fallback (for <64px contexts, email, or no-JS environments)

```html
<img src="https://cdn.shaughv.com/brand/shaughv/logos/SHAUGHV-Official.svg" alt="SHAUGHV" />
```

PNG fallbacks (`SHAUGHV-Green.png`, `SHAUGHV-Orange.png`) exist for clients that can't render
SVG (Outlook on Windows, certain image-processing pipelines). Prefer the SVG everywhere it works.

### React port of the brand mark

If the project is React + bundled (Vite, Next, etc.) and Framer Motion is acceptable, the
source JSX can be imported directly:

```jsx
// vendored from https://cdn.shaughv.com/js/react/AnimatedBrandMark.jsx
import AnimatedBrandMark from './AnimatedBrandMark.jsx'
```

It's raw JSX (no compilation upstream), so it needs a JSX-aware bundler. For static HTML
pages, prefer the vanilla `<shaughv-mark>` drop-in above — no build step, smaller bundle.

### Favicon (light + dark with `prefers-color-scheme`)

```html
<link rel="icon"
      href="https://cdn.shaughv.com/brand/shaughv/favicons/SHAUGHV-Favicon-Dark.svg"
      media="(prefers-color-scheme: light)" />
<link rel="icon"
      href="https://cdn.shaughv.com/brand/shaughv/favicons/SHAUGHV-Favicon-Light.svg"
      media="(prefers-color-scheme: dark)" />
```

The `-Alt` variants (`SHAUGHV-Favicon-Dark-Alt.svg`, `SHAUGHV-Favicon-Light-Alt.svg`) are
secondary marks — use them only when the primary mark conflicts with adjacent UI (e.g. on a
browser tab that already has a similar icon nearby). When in doubt, use the non-`Alt` files.

### Fonts (one stylesheet per family loads every weight)

```html
<link rel="stylesheet" href="https://cdn.shaughv.com/fonts/makira/makira.css" />
<link rel="stylesheet" href="https://cdn.shaughv.com/fonts/ibm-plex-mono/ibm-plex-mono.css" />
```

```css
:root {
  --font-display: "Makira", system-ui, sans-serif;
  --font-mono:    "IBM Plex Mono", ui-monospace, monospace;
}
```

The `.css` files contain `@font-face` blocks for every weight. Browsers only download the
weights they actually paint, so loading both stylesheets is cheap — they're a single request
each and the binaries are lazy-fetched.

### Font preload (perf, optional but recommended for above-the-fold text)

Typical SHAUGHV page paints `IBM Plex Mono Regular (400)` for body and `Makira Bold (700)` for
display headings. Preload those two so they're cached before the CSSOM resolves:

```html
<link rel="preload" as="font" type="font/woff2" crossorigin
      href="https://cdn.shaughv.com/fonts/ibm-plex-mono/woff2/IBMPlexMono-Regular.woff2" />
<link rel="preload" as="font" type="font/woff2" crossorigin
      href="https://cdn.shaughv.com/fonts/makira/woff2/Makira-Bold.woff2" />
```

The `crossorigin` attribute is required on font preloads even though CORS is open — browsers
won't reuse a preload across origins without it.

### Makira variable font (single request, all weights)

```css
@font-face {
  font-family: "Makira VF";
  src: url("https://cdn.shaughv.com/fonts/makira/variable/Makira-VF.ttf")
       format("truetype-variations");
  font-weight: 400 900;
}
```

Use this when animating font-weight, or to cut down on font requests in apps that paint many
weights. IBM Plex Mono does **not** ship a variable build on the CDN.

### Figurines (mascot illustrations)

```html
<img src="https://cdn.shaughv.com/brand/shaughv/figurines/figurine-header.webp"
     alt="" width="240" height="240" loading="lazy" />
```

Use the `transparent/` variants when overlaying on photographs, colored surfaces, or anything
non-cream:

```html
<img src="https://cdn.shaughv.com/brand/shaughv/figurines/transparent/figurine-header.webp"
     alt="" loading="lazy" />
```

Available figurines (each in both opaque and `transparent/` form):

- `figurine-header.webp` (+ `figurine-header.svg`) — primary hero figurine
- `figurine-footer.webp` — footer/closing context
- `figurine-mail.webp` — contact / email contexts
- `figurine-look-at-this.webp` — pointing / drawing attention
- `figurine-404.webp` (+ `figurine-404.svg`) — 404 / error states

### Loader (canonical loading indicator)

```html
<shaughv-loader style="color: var(--accent); height: 120px;"></shaughv-loader>
<script src="https://cdn.shaughv.com/js/shaughv-loader.js"></script>
```

Inherits color from CSS `currentColor` (via the inline `color:` here). Size by setting
`height` — width auto-derives.

## Cache contract — what URL stability means for you

| File class | `Cache-Control` | What this means |
|---|---|---|
| Fonts (`*.woff2`, `*.woff`, `*.ttf`, `*.otf`) | `public, max-age=31536000, immutable` | URL ↔ bytes for 1 year. **Never expect "the latest" to appear at the same URL** — new versions ship under new filenames. |
| Images (`*.svg`, `*.png`, `*.webp`) | `public, max-age=31536000, immutable` | Same as fonts — content-addressed. |
| `*.css`, `*.js`, `*.jsx` | `public, max-age=86400, stale-while-revalidate=604800` | Mutable drop-ins. Patches propagate within ~1 day; stale copies serve from cache while a fresh fetch runs in the background. |

**Practical consequences:**

- **No cachebusting needed on binary URLs.** Don't append `?v=1` query strings to font or
  image URLs — they're already content-addressed by filename. Adding a query string just
  defeats the cache.
- **Don't ask for "the new logo at the same URL."** If a binary asset is being updated, it
  ships under a new filename (e.g. `SHAUGHV-Official-v2.svg`). Old consumers keep working
  off the old URL; new consumers point at the new URL.
- **CSS/JS updates land within a day.** If the user just shipped a change to `makira.css`
  or `animated-brand-mark.js` and doesn't see it, either wait 24h, or have them manually
  purge the URL in the Cloudflare dashboard (zone: `shaughv.com` → Caching → Custom Purge).

## CORS

Open `*` on `GET` and `HEAD`. Allowed headers: `*`. Exposed headers: `ETag`, `Content-Length`,
`Content-Type`, `Cache-Control`.

In practice: any origin can `<link>`-load fonts, `<script>`-load the drop-ins, `<img>`-load
brand assets, or `fetch()` anything without preflight. The CDN is read-only — no `POST`,
no `PUT`, no auth.

## License — important, don't miss this

| Asset class | License | Can you redistribute? |
|---|---|---|
| SHAUGHV brand assets (logos, favicons, figurines) | © Emmett Shaughnessy, all rights reserved | **No.** Link to the CDN. Don't host copies elsewhere or ship them in third-party packages. |
| Makira Sans-Serif (display font) | Commercial license held by Emmett Shaughnessy | **No.** Self-hosting on this CDN is permitted under the license; redistributing the binaries (mirroring on another CDN, bundling in a package) is not. |
| IBM Plex Mono (monospace font) | SIL Open Font License 1.1 | **Yes**, under OFL terms — but in SHAUGHV projects, prefer the CDN URL for consistency and a single source of truth. |

If you're building something for a third party who's not under Emmett's brand umbrella,
don't link them to the SHAUGHV brand assets or Makira. They get IBM Plex Mono (or a Google
Fonts equivalent) and a generic icon set.

Quick decision matrix when an agent gets a fuzzy ask:

|---|---|
| "SHAUGHV logo" / "the wordmark" | `/brand/shaughv/logos/SHAUGHV-Official.svg` |
| "Animated logo" / "brand mark" / "the SHAUGHV mark that draws itself" | `<shaughv-mark>` via `/js/animated-brand-mark.js` |

| "Mascot" / "figurine" / "illustration" | `/brand/shaughv/figurines/figurine-*.webp` |

## What this skill is *not* for

- **Maintaining the CDN itself** (adding new assets, deploying, regenerating the URL map,
  editing CORS) — that workflow lives in the source repo's `CLAUDE.md` at
  `https://github.com/RealEmmettS/shaughv-cdn/blob/main/CLAUDE.md`. The same repo's README
  documents the wrangler + `scripts/deploy.sh` flow. This skill is for **consumers** of
  the CDN, not maintainers.
- **General SHAUGHV brand design** (color tokens, type scale, component patterns, full UI
  kits) — that's the `shaughv-design` skill in this same plugin. Reach for that when the
  user wants to build UI; reach for this skill when they need URLs.
